# Step 2 — `@tatara/http`

**Goal:** Move the HTTP plumbing (errors, envelope, validation hook, request context, error/404 handlers, health/ready, OpenAPI + docs, route mounting, server start) into `@tatara/http`. The app keeps `src/core/http/app.ts`, `context.ts` and `routes.ts` as short, readable wiring.

**Spec:** `docs/superpowers/specs/2026-10-30-framework-packages-design.md` (rule 6 "Hono stays Hono"; Packages table row `@tatara/http`).

## Package API

The package returns plain Hono objects:

| Export | What |
|---|---|
| `createApp<E>({ logger, cors: { origins, exposeHeaders?, allowHeaders? }, bodyLimitBytes, defaults? })` | `OpenAPIHono<E>` with request context (request id + request logger + `defaults` variables), secure headers, CORS, body limit, `/health`, `/ready` |
| `mountRoutes(app, routes, { app: name, prefix })` | `app.route(prefix + basePath, router)` for the routes of that app |
| `serveOpenApi(app, { title, version?, extend?(document) })` | `/openapi.json` (after `extend`) and `/docs` |
| `handleErrors(app, { message?(err, c) })` | error envelope for `AppError` / `HTTPException` / unknown errors, plus the 404 handler |
| `createRouter<E>()`, `defineRoutes`, `RouteDefinition<A, E>` | router with the validation hook |
| `startServer(app, { port, name, logger })` | node server + shutdown hook + signal handling (`@tatara/core`) |
| errors (`AppError`, `ValidationError`, `NotFoundError`, …), `success`, `paginated`, `jsonBody`, `jsonContent`, `errorResponses`, schemas, `validationHook`, `requestContext` | as in today's templates |

Peers: `hono`, `@hono/zod-openapi`, `@hono/node-server`, `@scalar/hono-api-reference`, `@tatara/core`.

## What the app keeps

- **`app.ts`:** `createApp` → feature middleware (slot) → feature routes (slot) → `mountRoutes` → `serveOpenApi({ extend })` (slot) → `handleErrors({ message })` (slot).
- **`routes.ts`:** `APP_NAMES` (slot), and `createRouter`/`defineRoutes` typed with the app's `AppEnv`.
- **`context.ts`:** the `AppEnv` and `Principal` types.

**Template fix:** better-auth adds `set-auth-token` to the CORS exposed headers (an `expose-headers` slot), so browser apps can read bearer tokens.

   - Move the i18n `error-message` slot from the error handler into `app.ts`.
