# Step 1 — `@tatara/core`

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:**
- Move commands, flags, lifecycle, readiness, logger options and `localDefault` from the templates into a published `@tatara/core` package.
- Generated apps import it.
- A `0.2.0` codemod moves existing apps (MeemAin) onto it.

**Architecture:**
- `packages/core` is scaffolded with `pnpm new-package core --peer zod --peer pino`.
- Functions that log take a logger argument, because packages never read app config.
- Templates drop the copied files and import from `@tatara/core`.
- The CLI depends on `@tatara/core` through `templates/versions.json`. e2e installs the packed local package through `TATARA_PACKAGE_SPECS`.

**Spec:** `docs/superpowers/specs/2026-10-30-framework-packages-design.md` (Packages table row `@tatara/core`; "How packages fit into an app"; "Ideas kept" 3).

## Global Constraints

- Everything in step 0's Global Constraints applies.
- **Versions:** `@tatara/core` starts at `0.1.0`. `@tatara/cli` and `create-tatara` become `0.2.0`, and the codemod's `version` is `"0.2.0"`.
- **No env reads in the package:**
  - No `process.env` and no `#core/config/env` imports. Values come in as arguments.
  - The one exception is `createLocalDefault(production)`, whose argument the app's `env.ts` computes.
- **Peers, not dependencies:** `zod` and `pino` are `peerDependencies` (pino is used for types only).
- **`sideEffects: false`:** module-level registries (shutdown hooks, readiness checks, `waitUntil` set) are state, not import-time work.

## Package API (`packages/core/src/index.ts`)

| Export | From today's template | Change |
|---|---|---|
| `defineCommand`, `noArgs`, `flag`, `CommandDefinition`, `CommandContext` | `core/commands/define.ts` | `CommandContext.logger` is `CoreLogger` |
| `parseFlags`, `runCommand(commands, argv, logger)` | `core/commands/runner.ts` | takes `logger` |
| `onShutdown`, `shutdown(code, logger?)`, `handleSignals(logger)`, `waitUntil(promise)` | `core/process/lifecycle.ts` | `waitUntil` is new: shutdown awaits pending promises, bounded by `shutdownTimeoutMs` (default 10 000), before running hooks in reverse order |
| `registerReadinessCheck`, `runReadinessChecks` | `core/http/health.ts` | unchanged |
| `loggerOptions({ env, level, service })`, `levelToSeverity` | MeemAin's `logging/options.ts` | production: `messageKey: "message"` + `severity`; development: pino-pretty; test: plain |
| `createLocalDefault(production: boolean)` | generated `env.ts` helper | returns `localDefault(schema, value)` |
| `type CoreLogger = { info(o: object, m?: string): void; error(o: object, m?: string): void; child(b: object): CoreLogger }` | — | pino's logger satisfies it |

The app keeps `src/core/logging/logger.ts` as config: `export const logger = pino(loggerOptions({ env: env.NODE_ENV, level: env.LOG_LEVEL, service: "__APP_NAME__" }))`.

## Review Focus

1. **`--force false` still disables a flag** once `flag()` lives in the package. *(Task 1, flags tests move with it.)*
2. **`waitUntil` work that never settles must not block shutdown forever.** Expected: shutdown proceeds after `shutdownTimeoutMs` and logs that it gave up. *(Task 1 test `stops waiting after the timeout`.)*
3. **An existing app with a modified `logger.ts`** (MeemAin has Cloud Logging options) must keep its file. Expected: the codemod reports it and leaves it alone. *(Task 3 test `keeps a customised logger`.)*
4. **A freshly published `@tatara/core` is refused by pnpm's minimum release age** in new apps. Expected: the template's `pnpm-workspace.yaml` excludes `@tatara/*`. *(Task 2 e2e.)*
5. **The `versions.json` entry for `@tatara/core` drifts from the package version.** Expected: a conventions test fails. *(Task 1.)*

### Task 1: The package

- [ ] Scaffold with `pnpm new-package core --peer zod --peer pino`, then set the version to `0.1.0`.
- [ ] **Tests first** in `packages/core/src/*.test.ts`:
  - **Flags:** today's `flags.test.ts` cases (bare, `false`, `=0`, `true`, default, invalid), plus `parseFlags` camel-casing.
  - **`runCommand`:**
    - lists commands for `--list` and returns 0
    - returns 1 for an unknown command
    - returns 1 and lists the issues for invalid args
    - returns 1 and calls `logger.error` when `run` throws
    - passes `logger.child({ command })` to `run`
  - **Lifecycle:**
    - hooks run in reverse order
    - a failing hook is logged and the rest still run
    - `shutdown` awaits `waitUntil` promises before the hooks
    - `stops waiting after the timeout` (fake timers)
    - with process exit replaced through an injectable `exit`, `shutdown(3)` calls `exit(3)`
  - **Readiness:** all ok → ready; one throws → `ready: false`, with that check `"failed"`.
  - **`loggerOptions` + `levelToSeverity`:** MeemAin's `options.test.ts` cases, with `service` taken from the argument.
  - **`createLocalDefault`:**
    - `createLocalDefault(false)(z.url(), "http://x")` parses `undefined` to `"http://x"`
    - with `true`, it rejects `undefined`
- [ ] Watch them fail, implement, watch them pass: `mise exec node@24 -- pnpm vitest run packages/core`.
- [ ] Add `"@tatara/core": "0.1.0"` to `packages/cli/templates/versions.json`.
- [ ] Add a conventions test: every `@tatara/*` key in `versions.json` equals that package's `version`. Watch it fail before the entry exists, then pass.
- [ ] Build (`pnpm --filter @tatara/core build`), check the output has `dist/index.mjs` and `dist/index.d.mts`, and that the size is well under 500 KB.
- [ ] `pnpm verify`, then commit: `feat(core): @tatara/core with commands, flags, lifecycle, readiness, logger options, localDefault`.
